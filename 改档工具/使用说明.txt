AZS 存档修改器 —— 改「重置次数 / 特权等级 / 统计数值」
=========================================================

一、这是干什么的
----------------
游戏的存档是 %APPDATA%\wenilla-rogue\characters.txt，
内容形如 "RSE1:" + 一长串 base64。解出来是 16 字节盐 + 密文 + 20 字节校验 tag，
所以记事本打开看到的是乱码，直接改会把存档改坏。

这个工具能把存档解成明文、改几项常用的值、再原样加密写回去，
写之前自动备份，写完自动回读校验一遍。

你现在最关心的那件事：存档里 resets|2 表示「已经用掉 2 次重置」，
游戏每次开档只给 2 次，所以界面上显示「剩 0 次」。
工具里点一下「清零（恢复 2 次重置）」，再写入，就能重新分配特权点数了。


二、怎么用
----------
1. 先完全退出游戏（重要！游戏在跑的话，它下次自动存档会把你的改动盖掉）。
2. 双击 存档修改器.cmd，等 5~10 秒（要读一遍游戏 exe，用来算密钥流）。
3. 改你要改的项：
   - 重置次数：点「清零（恢复 2 次重置）」。
   - 特权等级：可以逐个填，也可以点「全部拉满」。表里的「上限」就是游戏
     允许的最高级，填超了会被夹回去；右边会实时显示「预计花费」多少点。
   - 统计数值：金币、牌子、击杀、宝箱、局数、胜利，只影响面板显示。
4. 点「写入存档」。底部会显示写入结果和备份文件名。
5. 开游戏，进「军械库 → 奖励 → 特权」确认。

想改别的字段：切到「原文编辑」页，那里是解出来的完整明文，一行一条，
改完直接点「写入存档」即可（工具会先自检能不能重新加密回去，失败就不写）。

四、加密是怎么解出来的（原理）
------------------------------
存档结构：RSE1: + base64( 盐16字节 | 密文 | tag20字节 )

  解密 = 用（盐, 偏移）生成密钥流，逐字节 XOR；
  tag  = 用游戏内部那个哈希函数算 SHA-1 变体（"tag" | 盐 | 密文）。

那个哈希不是标准 SHA-1（它带一块硬编码前置块，等价于一种 keyed hash），
纯 Python 复现不了，所以这个工具的做法是：
**把游戏 exe 的代码段映射进自己的进程，直接调用游戏自己的两个函数**
（0x5b44860 生成密钥流、0x5b44ae0 算 tag），
把 IAT 修正到本进程的真实 API 之后再调用。

好处是：不需要知道内部密钥，也不怕它换密钥。
坏处是：依赖 exe。游戏一更新，这两个函数地址可能变，到时候工具会读不出来
（会明确报错，不会写坏存档）。

验证过的：拿解出来的明文重新加密，能逐字节复现原来的 characters.txt。


五、安全吗 / 出问题怎么办
--------------------------
- 每次写入前都会把旧存档复制到 %APPDATA%\wenilla-rogue\改档备份\，
  文件名带时间戳，界面上「打开备份目录」可以直接打开。
- 写入后会立刻回读校验，解不回来会当场报错。
- 另外这个目录下还有一份改动前的独立备份：
  F:\yx\AzerothSurvivors\存档备份_20261031\characters-改档前-*.txt
- 游戏自己也会每小时在 %APPDATA%\wenilla-rogue\Saves\ 留一份（留 5 份）。

要还原：把备份文件复制回 %APPDATA%\wenilla-rogue\characters.txt 覆盖即可
（注意备份本身就是 RSE1 格式，直接覆盖就行，不需要解密）。


六、已知局限
------------
- 特权表是靠扫描 exe 认出来的（13 条，id/名称/每级花费）。
  游戏大更新后如果认不到表，界面上的特权区会是空的，
  这时「重置次数」和「原文编辑」仍然能用。
- 没有校验「点数够不够」：全部拉满的花费可能超过你成就拿到的点数，
  游戏那边会怎么显示没测过（大概率只是显示负数或不允许再花）。
  想稳妥就只改重置次数，把点数退还后自己重新分配。
- tag 校验依赖游戏 exe 里的函数；如果哪天游戏换了加密方案，
  工具会报「tag 校验失败」而不是写坏文件。
